## 0. 构建 / 发布 / 环境（每次都要用，务必先看）

### 构建（本机是 arm64 Android 容器，SDK 的 aapt2/aidl 是 x86-64 不能直接跑）

```bash
cd "/sdcard/AndroidCSProjects/DeepSeekHarness"
LC_ALL=C.utf8 LANG=C.utf8 timeout 1400 \
  sh /root/tools/build-dsh.sh :app:assembleStandardRelease :app:assembleLowRelease
```

- `/root/tools/build-dsh.sh`：包装脚本，注入 `-I /root/aidl-shim/aidl-shim.gradle`（禁用 Aidl 任务、用预生成 `IShellService.java`）
  和 `-Pandroid.aapt2FromMavenOverride=/root/tools/aapt2`（qemu 包装的 x86-64 aapt2）。
- **必须用 `sh gradlew`（不是 `./gradlew`）**：/sdcard 是 noexec 挂载。
- 若报 `duplicate class: com.deepseekharness.app.IShellService`：删 `app/build/generated/aidl_source_output_dir` 后重试。
- 若报 `Input/output error`（compress*Assets）：sdcard FUSE 偶发，直接重试一次即可。
- 产物：`app/build/outputs/apk/{standard,low}/release/app-*-release.apk`

### 版本号

- `app/build.gradle`：`versionCode` 每发一版 +1（当前 178），`versionName "20261002-rc2"`（low 自动加 `low` 后缀）。
- 交付目录：`/sdcard/Download/DeepSeekHarness/DeepSeekHarness-20261002-rc2-{standard,low}-release.apk`

### GitHub 推送（github.com 被网络屏蔽！）

- **`github.com` 不可达**（TCP 不通/TLS 被重置），`api.github.com`、`uploads.github.com`、`ssh.github.com:443` 可达。
- 所以 **git push 不能用**，改用 **GitHub Git Data API** 推送：脚本 `/tmp/gitdata_push.py`
  （blobs → trees → commits → refs；要点：`--topo-order` 保证父先于子、提交 author/committer 与时间戳必须与本地一致、
  提交 message 只去掉 git log 自带的最后一个换行，否则 sha 不匹配；base_sha 必须用**远端真实 ref**）。
- Push token：由用户提供（fine-grained PAT，repo 权限）。**不要把 token 写进仓库文件**。
- 推送后同步本地 tracking：`git update-ref refs/remotes/origin/main <远端sha>`。

### Release 发布

- 仓库：`xliaoy/DeepSeekHarness`；release tag 固定 `20261002-rc2`，release id `402072197`。
- 资产名必须与 App 更新解析匹配：`app-standard-release.apk` / `app-low-release.apk` + 同名 `.sha256`。
- 换资产流程：列 assets → 逐个 DELETE → 上传 4 个新资产（APK 上传用 `--retry 4 --retry-all-errors`，网络易中断）。

## 1. 用户需求总表（按提出顺序）

### 1.1 终端（已完成 ✓）
- **默认必须是 PTY 终端**（用户要"我原来的 PTY 那种"），不是简易终端。
  → `PtyTerminalFragment.preferred()` 默认值 `true`（KEY_PTY 默认 PTY）。
- **关闭终端要"秒关"**，不能等。
  → `PtySession.finishAndWait`：身份未确认只等 300ms；回收预算 ≤2s；超时/核验失败**一律直接收尾移除标签**不抛异常；
  `TerminalSessionOwner.closePty` 异常也移除（对齐简易终端语义）；UI 关闭超时 5000→2000ms。

### 1.2 在线更新页（已完成 ✓）
- 用户原话：*"更新要弄成两个，一个更新 app 本体，一个更新运行时版本，都要可以自选更新的版本，不能降级只能升级自选版本，
  选中版本后可以直接查看更新日志，弄成 tab 切换的形式"*。
  → `UpdateActivity`：两个 tab（软件更新 / 运行时更新）；App 侧 `UpdateEngine.availableReleases()` 只列**比当前新**的版本；
  运行时侧 `DshUpdater.selectVersion` 拒绝 ≤ 当前版本；选中版本弹 CardSheet 显示更新日志
  （App 用 release notes；运行时用 `DshUpdater.fetchNotesAsync` 按 tag 拉 GitHub release notes）。
- **更新源 = 用户自己的 GitHub releases**（`https://api.github.com/repos/xliaoy/DeepSeekHarness/releases`），
  不是已失效的 `deepseekharness.cc`（该域名已过期挂出售页，返回 HTML）。
- **版本比较必须用 `comparableCode(versionName)`**（tag 是日期数值 20261002，与真实 versionCode 177 不同体系，
  混用会导致"已是最新仍提示更新"）。
- 已恢复 `DshUpdater`（用户版，577 行）+ `DeepSeekHarnessApp.onCreate` 里的 `cancelPendingRestart` 钩子。

### 1.3 侧边栏 / 设置（已完成 ✓）

### 1.5 交付文件「用其他应用打开」（已完成 ✓）
- 目标：交付文件能直接用手机上的其它软件打开/查看/编辑。
- **方案：不用新写桥**，用已有的 App 桥 `/app/openfile` + `/app/share`（3090）。
- 用户指定**用分享方式**：插件优先 → 复制到 `/sdcard/Download/DeepSeekHarness` → `/app/share` 弹分享面板；
  兜底 → 复制到容器 `/tmp` → `/app/openfile` 打开方式选择器。
- 修过的坑（都要保留）：
  1. 插件 `resolveDeliverablePath` 必须读 `readEvent(...).target`（事件本体在 `.target` 下），失败要回显**具体原因**。
  2. App 桥响应统一是 JSON `{"result":"..."}` —— 插件必须解析 `result` 字段判定 OK（不能 `startsWith('OK')`）。
  3. `/app/share` 原来用 `Uri.fromFile`（file://）→ Android 7+ 抛 `FileUriExposedException`；
     改为 `DownloadsExport.write` 导出到公共 Download 拿 **content URI** 再分享。
  4. `DownloadsExport` 的 MIME 原来是"非 txt/zip 一律 gzip"→ 接收方按 gzip 处理、文件名被加 `.gz`；
     改为 `URLConnection.guessContentTypeFromName` **动态识别**（不能固定 MIME，文件可能是任意格式）。
  5. 文件名要保留**原始名（含中文）**（`name` 参数传给 App），不能显示 `dsh-deliverable-<随机>` 临时名。
  6. **token 每次重启/重进都会轮换** → App 桥 `tokenMatch` **只要 rootfs 的 `.bridge_token` 文件有效就一律以文件为准**
     （不依赖内存快照）；插件 `callBridge` 遇 `UNAUTHORIZED` 会**重读 token 重试一次**。
  7. 敏感路径策略 `BridgePathPolicy` 会拒绝 `/root/.dsh` 等前缀 → 插件用 `/tmp`、`/sdcard` 副本绕开（副本用后即删，
     凭据导出防护不降级）。

### 1.6 权限门禁（已完成 ✓）
- **进入 App 时强制申请「所有文件访问」权限**：不授权不进入主界面（弹窗只有「去授权」「退出」，不可取消）；
  从系统设置返回仍未授权继续弹。→ `MainActivity.onCreate/onResume` + `showStoragePermissionGate()`。

### 1.7 APK 体积（已完成 ✓）
- 用户问"为什么这么大、有没有无用文件"。
- 根因：`recovery-rootfs.bin` 与 `offline-rootfs.bin` **解压内容完全相同**（同一个 301MB rootfs），
  但压缩参数不同导致 sha 不同 → `RecoveryArchiveSource` 的共享去重校验失败 → 重复打包 86MB。
- 修复：`tools/recovery-runtime/lock.json` 里 `recovery-rootfs.bin` 的 sha 对齐 `offline-rootfs.bin`，
  archives 副本也替换为同一文件 → 共享生效，APK 各减 **86MB**（standard 364→278M，low 439→353M）。
- 可能进一步裁剪（用户未选）：LibreOffice WASM 127M、cua 驱动 39M、sherpa 语音 34M、low 版 Gecko 140M。
